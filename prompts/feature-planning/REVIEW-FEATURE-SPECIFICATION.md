# REVIEW-FEATURE-SPECIFICATION

## Título

Revisar especificação de Feature

## Papel do agente

Business Analyst Agent, QA Agent ou Architect Agent

## Objetivo

Avaliar se a Feature está consistente, rastreável e pronta para execução.

## Contexto esperado

Feature existente aguardando validação de especificação.

## Documentos obrigatórios para leitura

- `FEATURE.md`
- `EPIC.md`
- `BUSINESS-RULES.md`
- `USE-CASES.md`
- `WORKFLOWS.md`
- ADRs relacionadas

## Entradas necessárias

- Feature alvo
- critérios de aceite
- dependências

## Escopo permitido

- revisão
- proposta de ajustes documentais

## Restrições

- não alterar silenciosamente requisitos aprovados

## Procedimento de execução

1. revisar objetivo e escopo;
2. verificar regras e rastreabilidade;
3. validar critérios;
4. classificar lacunas e riscos.

## Validações obrigatórias

- Feature vinculada à Epic
- critérios verificáveis
- fora do escopo definido

## Critérios de conclusão

- parecer claro sobre prontidão da Feature

## Formato do relatório final

- conforme
- parcialmente conforme
- não conforme
- ajustes recomendados

## Política de Git

Preferir relatório; só alterar documentos se autorizado.

## Tratamento de inconsistências

Registrar conflito com regras ou arquitetura.

## Tratamento de informação ausente

Indicar itens faltantes antes de permitir execução.

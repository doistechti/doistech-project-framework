# Contribuindo com o DoisTech Project Framework

## Objetivo

As contribuições para o DPF devem preservar a consistência da metodologia,
sua independência tecnológica e sua capacidade de ser utilizada por humanos
e agentes de Inteligência Artificial.

## Regras gerais

Toda contribuição deverá:

- possuir escopo claramente definido;
- respeitar a especificação oficial;
- preservar compatibilidade com a hierarquia documental;
- evitar dependência de tecnologia específica;
- incluir justificativa para alterações normativas;
- atualizar documentos relacionados quando necessário;
- informar impactos sobre templates, exemplos e prompts.

## Alterações normativas

Mudanças na metodologia não devem ser feitas diretamente.

Uma mudança normativa deverá ser acompanhada de:

1. descrição do problema;
2. justificativa;
3. proposta de alteração;
4. impacto esperado;
5. riscos;
6. compatibilidade com versões anteriores;
7. documentos afetados.

## Commits

Utilize mensagens de commit claras e objetivas.

Exemplos:

```text
docs: add DPF specification
docs: add feature template
chore: initialize repository structure
fix: correct task status terminology
refactor: reorganize governance documents
```

## Pull requests

Uma pull request deverá informar:

* objetivo;
* escopo;
* arquivos alterados;
* impacto metodológico;
* validações realizadas;
* pendências;
* riscos conhecidos.

## Restrições

Não são aceitas alterações que:

* contradigam documentos aprovados;
* introduzam tecnologia obrigatória;
* misturem especificação com implementação;
* removam rastreabilidade;
* permitam alterações silenciosas por agentes;
* substituam documentos oficiais por exemplos.
